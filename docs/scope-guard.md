# ScopeGuard Configuration

ScopeGuard configuration generated by the `/setup-toolkit-scope-guard` skill.

## Purpose

ScopeGuard is a first-party CLI that gives PHP the namespace visibility Rust spells `pub(crate)`,
`pub(super)`, and `pub(in path)`. PHP has two levels for anything a namespace exports — `public`,
which is public to the whole program, and nothing — so every helper a package needs internally is
reachable from everywhere, and the first caller outside the package that names it turns an
implementation detail into public API.

A declaration states its scope with a `@visibility` tag, and `scope-guard` reports every place the
sources name it from outside that scope.

```php
namespace App\Billing\Ledger;

/**
 * Appends entries to the ledger file.
 *
 * @visibility parent
 */
final class LedgerWriter
{
    public function append(Entry $entry): void { /* ... */ }
}
```

```
1. src/Http/InvoiceController.php:24 [out_of_scope]
   symbol: App\Billing\Ledger\LedgerWriter
   message: Class App\Billing\Ledger\LedgerWriter is not visible from namespace "App\Http": the
     declaration is marked "@visibility parent", so it may only be named from namespace "App\Billing"
     and its sub-namespaces. Move this instantiation into that namespace, or widen the declaration to
     "@visibility App".
```

The tag is ScopeGuard's own, not an extension of anyone else's vocabulary. It is checked by this
command, not by PHPStan: a static analyser's tag namespace belongs to that analyser, and a project
that adopts namespace visibility should not have to adopt a particular analyser with it.

## Command

Run:

```bash
vendor/bin/scope-guard --config=scope.yaml
```

Exit codes:

- `0`: no violations
- `1`: visibility violations found
- `2`: configuration or runtime error

## The `@visibility` Tag

A scope is one namespace plus everything below it, the way a Rust module contains its descendants.
The declaring namespace is always inside its own scope, so a declaration never hides from the code
next to it.

| Scope | Rust equivalent | Visible from |
|-------|-----------------|--------------|
| `public` | `pub` | Everywhere. Same as leaving the tag off; write it to state the intent. |
| `root` | `pub(crate)` | The outermost segment of the declaring namespace and everything below it. |
| `parent` | `pub(super)` | The namespace directly above the declaring one, and everything below it. |
| `namespace` | `pub(self)` | The declaring namespace and its sub-namespaces only. |
| `App\Billing` | `pub(in path)` | The named namespace and its sub-namespaces, plus the declaring namespace. |

For a grandparent and beyond, name the namespace: `@visibility App\Billing` says more about the
design than "two levels up" does, and it survives a move of the declaring class.

Several tags union. `@visibility namespace` plus `@visibility App\Console` opens the declaration to
its own namespace and to the console namespace, and to nothing else.

A namespace whose first segment is a single lowercase word collides with the keywords, so write it
with a leading backslash: `@visibility \legacy` names the namespace `legacy`, while
`@visibility legacy` is reported as a mistyped keyword.

Like every PHPDoc tag, `@visibility` only counts at the start of a comment line. Prose that names the
tag while explaining it is text, not a declaration.

### Where the tag can go

- Classes, interfaces, traits, and enums — restricts the whole type.
- Methods, properties, class constants, and enum cases — restricts one member of an otherwise public
  type. A member is never wider than its type: a `@visibility namespace` class keeps its untagged
  public methods inside that namespace too.

A scoped constructor is how a class stays publicly usable while only its own namespace may build it:

```php
final class Connection
{
    /**
     * @visibility namespace
     */
    public function __construct(private Socket $socket) {}
}
```

## What ScopeGuard Checks

ScopeGuard resolves names, not types. It parses each source file, applies the file's namespace and
its import table to every written name, and matches the result against the declarations it found.
That is the same question a module system asks — which paths may name this item — and it needs no
type inference to answer.

| Reference | Example |
|-----------|---------|
| instantiation | `new LedgerWriter()` |
| static call | `LedgerWriter::open()` |
| static property access | `LedgerWriter::$open` |
| constant access | `LedgerWriter::MODE`, `Suit::Hearts` |
| class name reference | `LedgerWriter::class` |
| instanceof check | `$value instanceof LedgerWriter` |
| inheritance | `extends`, `implements` |
| trait use | `use LedgerTrait;` |
| parameter, return, property type | `function write(LedgerWriter $writer): ?LedgerWriter` |
| catch type | `catch (LedgerFailure $failure)` |
| attribute | `#[LedgerMarker]` |

Member scopes are enforced wherever the member is reached through a named class, which covers
`X::method()`, `X::CONST`, `X::$prop`, and the constructor behind `new X()`. A member reached through
a variable — `$writer->append()` — is not resolved, because the type of `$writer` is not a name. The
class scope still holds there: the object had to be named somewhere to exist, and that name is
checked.

`self`, `static`, and `parent` are never reported. They can only name the class the reference is
already inside or one it inherits from, and that inheritance is checked where it is declared.

Member lookups follow declared parents, so a scope written on an inherited member answers for the
child class a reference names.

### Unusable tags

A scope that cannot be honoured is reported at the declaration under `invalid_scope`, because a tag
that silently resolves to nothing would drop the restriction it was written to add:

```
2. src/Billing/Ledger/LedgerWriter.php:8 [invalid_scope]
   symbol: App\Billing\Ledger\LedgerWriter
   message: Fix "@visibility parrent" on class App\Billing\Ledger\LedgerWriter: one bare lowercase
     word is read as a scope keyword, and "parrent" is not one of "public", "root", "parent",
     "namespace"; write the keyword you meant, or write "\parrent" to name the namespace.
```

The same applies to `@visibility parent` on a class in a root namespace (its parent is the global
namespace, which restricts nothing), to any scope keyword on a class in the global namespace, and to
`@visibility public` written next to a narrowing tag.

Because an unusable tag restricts nothing, one mistyped tag produces one violation at the
declaration instead of a violation at every reference.

## Configuration

Example `scope.yaml`:

```yaml
paths:
  - src

exclude:
  - 'src/Generated/*'

exempt_namespaces:
  - 'Tests'

report:
  reporter: ai
  order_by:
    - path
    - line
```

`paths` (default `['src']`) lists the files and directories to scan, relative to the config file
directory. Both declarations and references are read from these paths: a class outside them is
never checked, and code outside them is never reported.

`exclude` (default `[]`) is a list of fnmatch globs applied to project-relative paths. `*` crosses
`/` boundaries, so `src/Generated/*` removes a whole subtree.

`exempt_namespaces` (default `[]`) lists namespace prefixes whose code may name any declaration
regardless of its scope. A prefix exempts its whole subtree. Unusable tags are still reported inside
an exempt namespace — a tag that cannot be honoured is wrong wherever it is written.

Tests are the usual entry. PHP has no counterpart to Rust's `#[cfg(test)] mod tests` declared inside
the module it covers, so a unit test of a namespace-scoped class necessarily sits in another
namespace. If the project scans its tests, exempt them:

```yaml
exempt_namespaces:
  - 'Tests'
```

## Reporter

`report.reporter` (default `ai`) selects the output format:

- `ai` — a structured report with per-violation remediation actions, intended for coding agents. The
  first line is `SCOPE_GUARD_PASSED` or `SCOPE_GUARD_FAILED`.
- `text` — concise human output.
- `json` — machine output for CI and other consumers.

`report.order_by` (default `['path', 'line']`) decides the order violations are printed in. Supported
fields are `path`, `line`, `rule`, and `symbol`. The order is decided by ScopeGuard rather than by
discovery order, so the same sources produce the same report on every platform and PHP version.

## How to Fix a Violation

### Move the reference into the scope

The usual answer: the code that wants the internal class belongs beside it.

### Give the namespace a public front door

When several namespaces want the same internal class, that is a missing entry point, not a missing
permission. Keep the internals scoped and export one public type from the owning namespace.

### Widen the declaration

If the scope was drawn too narrowly, widen it. Every message names the narrowest scope that would
admit the reference, so the fix does not have to be guessed.

Deleting the tag is not a fix. It removes the boundary instead of respecting it, which is the change
the tag exists to make visible.

## Relationship to DocGen

`doc-gen` reads the same tag. A scoped declaration carries a **Restricted visibility** notice on its
generated page, stating the scopes exactly as written, so the documentation says what is public API
and what is not. DocGen only reports the declaration; ScopeGuard is what enforces it.

## Prior Art

The tag has three ancestors, and borrows something from each:

- **phpDocumentor 1.x `@access private|protected|public`** — the original PHPDoc visibility tag,
  dropped once PHP gained real visibility keywords. It named the concept but could only repeat what
  the language already said.
- **PSR-19 `@internal`** — marks an element as internal to the project. It carries no scope, and
  nothing checks it.
- **Psalm `@psalm-internal Foo\Bar`** — restricts usage to a named namespace. This is the closest
  existing specification, and `@visibility Foo\Bar` means the same thing.

`@visibility` is a separate tag rather than a reuse of `@internal` because `@internal` accepts free
text (`@internal do not use`), which cannot be told apart from a scope. A dedicated tag keeps every
value meaningful, so a typo is a violation instead of a silently different scope.
