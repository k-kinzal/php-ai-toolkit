Guard CLI

Invoke vendor/bin/guard COMMAND from the project root. No command means check. Use guard COMMAND --help to confirm the installed version's options.

Commands

CommandBehavior
rulesList effective rules after imports and overrides, without reading target files.
checkReport violations without modifying files.
fix --dry-runShow proposed configuration diffs without writing them.
fixApply supported repairs, then report remaining violations.
baselineWrite all current violations to a baseline; leave source and configuration files unchanged.
initCreate a policy from detected presets and legacy policies; refuse to overwrite an existing policy.

Options

Applies toOptionMeaning
All policy commands-c, --config=FILEPolicy path relative to the working directory; default guard.yaml.
rules, check, fix, baseline--format=text|human|ai|jsonDefault ai in detected agent sessions, otherwise text; human aliases text.
rules, check--query=TEXTCase-insensitive literal search across rule IDs, paths, messages, levels, and fixability.
check--fixableDisplay only findings with automatic repair support.
check--level=error|warningDisplay one severity.
check--baseline=FILEBaseline relative to the policy directory; default guard-baseline.json there, if present.
check--no-baselineDisable suppression; incompatible with --baseline.
baseline-o, --output=FILEBaseline destination relative to the policy directory; default guard-baseline.json. Parent directory must exist.
init--import=NAMESComma-separated or repeated preset names; replaces automatic detection.

Check filters combine with AND and affect only displayed findings. Baseline suppression happens first. Neither filters nor baselines limit fix.

Reports and exit codes

CodeMeaning
0No active required violation; warnings may remain. rules, init, and baseline completed successfully.
1Active required violations remain, including ones hidden by display filters.
2Invalid command, policy, input document, baseline, or extension. Read stderr's Guard error: message.

baseline exits 0 after writing successfully even when it recorded violations. fix --dry-run reports whether the planned result would pass; exit 0 does not mean the files already comply.

rules --format=json returns rules and count. Each rule includes id, target, level, fixable, message, and resolved details.

Check and fix JSON includes findings, changes, diffs, action, success, and summary. Findings contain path, rule, level, message, and fixable. summary counts displayed findings; when filtering or a baseline is active, use totalSummary and selection to account for hidden active findings, and baseline for suppression counts. success: false corresponds to exit 1. Errors with exit 2 are stderr diagnostics, so check the exit code before parsing stdout as JSON.

action is checked, changed, would change, or blocked. Proposed diffs with blocked are not applied. changes uses absolute paths; finding and diff paths are relative to the policy directory.

For an unexpected missing finding, inspect the selected policy, automatic baseline, display filters, and collect scope. For exit 2, correct the named input before rerunning; it is not a policy violation to suppress.
