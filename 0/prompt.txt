## 1. tree.yaml schema (the contract)

```yaml
paths:                      # list&lt;string&gt;, default ['src']; dirs relative to config dir (absolute allowed)
  - src
  - tests/Unit

exclude: []                 # list&lt;string&gt; path globs relative to config dir; matching files are ignored,
                            # matching directories are pruned (entire subtree skipped)

rules:                      # list of rule blocks, default []
  - path: 'src/*'           # REQUIRED. Directory pattern (semantics below)
    max_files: 20           # int &gt;=1: max direct child files
    max_dirs: 10            # int &gt;=1: max direct child subdirectories
    max_total_files: 200    # int &gt;=1: max recursive file count under the matched dir (inclusive)
    max_depth: 3            # int &gt;=1: max directory nesting depth below the matched dir
    allow: ['*.php']        # list of basename globs; every direct child file must match at least one
    deny: ['*Helper.php']   # list of basename globs; no direct child file may match any
    allow_dirs: ['[A-Z]*']  # same as allow, for direct child directory names
    deny_dirs: ['Helpers']  # same as deny, for direct child directory names
    require: ['README.md']  # exact file names that must exist as direct children
    forbid_empty: true      # bool, default false: matched dir must not be empty
    file_case: pascal       # pascal|camel|snake|kebab: case convention for direct child file names
    dir_case: pascal        # same for direct child directory names

report:
  reporter: ai              # ai|text|json, default ai
  order_by: [path, rule]    # fields: path, rule, actual, limit; default [path, rule]
```

**Decided semantics (specify these verbatim in docs/tree-guard.md):**

- **Pattern matching is segment-aware**, not raw `fnmatch` on the whole path. The pattern and the config-root-relative directory path are split on `/`. A segment of exactly `**` matches **zero or more** path segments; every other segment must match exactly one path segment via `fnmatch()` (so `*`, `?`, `[...]` never cross `/`). Patterns are anchored at both ends. Examples: `src` matches only `src`; `src/*` matches direct children of `src` only; `src/**` matches `src` itself and every descendant; `**/Rule` matches any directory named `Rule` at any depth. Rationale: a tree-structure tool must distinguish "direct children" from "all descendants"; plain `fnmatch` (where `*` crosses `/`, as in LocGuard's exclude handling) cannot. Divergence from gitignore (`a/**` there excludes `a` itself) is deliberate for a one-rule-no-exceptions spec and must be documented.
- **Matchable directory set** = each `paths` entry directory itself + all non-excluded descendant directories. `exclude` still uses plain LocGuard-style `fnmatch` against the relative path (consistent with `loc.yaml` excludes; document the difference from `rules[].path`).
- **Multiple matching rules all apply independently.** No first-wins/merging. Rationale: constraints are additive guardrails; ordering-dependent override semantics create silent shadowing that is hostile to both humans and AI agents. Each violation carries the originating rule's `pattern`, so overlapping rules stay individually identifiable.
- **Absent constraint = unchecked.** `allow: []` (present but empty) means "no files allowed" — the reader must distinguish absent (null) from empty list.
- **"Exactly these names"** is expressed by composition, not a separate key: `require: [a, b]` forces presence, `allow: [a, b]` forbids anything else (exact names are valid globs). No `only:` key — one way to say it.
- **Counts:** `max_files`/`max_dirs` count non-excluded direct children only. `max_total_files` counts all non-excluded files in the subtree including direct children. The limit value itself passes (LocGuard convention: 50-line method passes at limit 50).
- **Depth:** measured relative to the matched directory; a matched dir with no subdirectories has depth 0; `src/PhpUnit/TestReporter/Subscriber` is depth 3 relative to `src`. Files never add depth. One violation is emitted **per offending descendant directory** (its own depth as `actual`), so each violation names exactly the directory to flatten.
- **Empty:** `forbid_empty: true` fires when a matched directory has zero non-excluded direct entries (files and dirs).
- **Case conventions:** checked against the file basename with everything from the first `.` stripped (`AiReporter.php` → `AiReporter`; `phpunit.xml.dist` → `phpunit`); dotfiles (leading `.`) are skipped. Directory names are checked whole. Regexes: pascal `^[A-Z][A-Za-z0-9]*$`, camel `^[a-z][A-Za-z0-9]*$`, snake `^[a-z0-9]+(_[a-z0-9]+)*$`, kebab `^[a-z0-9]+(-[a-z0-9]+)*$`.
- **Validation** (all errors `Invalid tree.yaml: ...`, thrown as `TreeGuardException`, exit 2, mirroring `ConfigScalarReader` message style): top level must be a mapping; `rules` must be a list of mappings; each rule requires non-empty string `path`; counts are ints ≥ 1; `file_case`/`dir_case` in the enum; `forbid_empty` bool; **unknown keys inside a rule block are rejected** with `Invalid tree.yaml: "rules[0]" contains unsupported key "max_file".` (deliberate divergence from LocGuard's ignore-unknown-limits behavior — a typo in a constraint key must not silently disable the check).
- If a `paths` entry is missing → `Configured path does not exist: %s`; if it is a file → `Configured path is not a directory: %s` (LocGuard allows file path entries; tree-guard is directory-scoped).

## 2. Violation model and rule identifiers

`src/TreeGuard/Analysis/Violation.php` — same `__get()` + `@property-read` + `/** @readonly */` promoted-private idiom as `src/LocGuard/Analysis/Violation.php`, but **no `line` field** (violations are directory/file scoped) and a new `pattern` field:

| field | type | meaning |
|---|---|---|
| `path` | string | offending dir, or offending/missing file path, relative to config root |
| `rule` | string | rule id below |
| `pattern` | string | the `rules[].path` pattern of the rule block that fired |
| `actual` | ?int | measured value; null for name-based rules |
| `limit` | ?int | configured limit; null for name-based rules |
| `message` | string | imperative, self-contained |

Rule ids and message templates (path column = Violation::path):

| rule id | path | message template |
|---|---|---|
| `max_files` | dir | `Directory "src/PhpStan/Rule" contains 82 files but the limit is 20. Move or merge files until at most 20 remain.` |
| `max_dirs` | dir | `Directory "src" contains 9 subdirectories but the limit is 8. Merge or flatten subdirectories.` |
| `max_total_files` | dir | `Directory "src/PhpStan" contains 97 files in total but the limit is 80. Restructure or split the subtree.` |
| `max_depth` | offending descendant dir | `Directory "src/A/B/C/D" is nested 4 levels below "src" but the limit is 3. Flatten the directory structure.` |
| `disallowed_file` | file | `File "src/notes.txt" does not match any allowed pattern (*.php). Rename, move, or delete it.` |
| `denied_file` | file | `File "src/Foo/BarHelper.php" matches denied pattern "*Helper.php". Rename or remove it.` |
| `disallowed_dir` | dir | `Directory "src/tmp" does not match any allowed pattern ([A-Z]*). Rename, move, or delete it.` |
| `denied_dir` | dir | `Directory "src/Helpers" matches denied pattern "Helpers". Rename or remove it.` |
| `missing_required_file` | `&lt;dir&gt;/&lt;name&gt;` of the missing file | `Directory "skills/setup-toolkit-tree-guard" is missing required file "SKILL.md". Create it.` |
| `empty_directory` | dir | `Directory "src/Empty" is empty. Delete it or add its intended contents.` |
| `file_case` | file | `File name "my_reporter.php" in "src/Reporting" does not follow the pascal convention. Rename it.` |
| `dir_case` | dir | `Directory name "error_formatter" does not follow the pascal convention. Rename it.` |

## 4. Analysis algorithm (exact)

1. `ConfigLoader::load(resolvedPath)` → `TreeGuardConfig` (root = `dirname(configPath)`).
2. `DirectoryTreeScanner::scan(config)` → `array&lt;string relDir, DirectoryListing&gt;`: for each `paths` entry, resolve absolute (`TreeGuardPathResolver::absolute`), assert directory, walk depth-first; at each dir, `DirectoryListingReader::read` (policy filters both files and dirs; an excluded dir is neither listed nor entered); record listing under `TreeGuardPathResolver::relative(root, dir)`; union-merge maps (`+=`, first wins on overlap, like `PhpFileFinder`), then `ksort`.
3. `TreeGuardAnalyzer::analyze(config)`:
   ```
   violations = []
   foreach config-&gt;rules as ruleConfig
       foreach listings as relDir =&gt; listing
           if DirectoryPatternMatcher::matches(ruleConfig-&gt;pattern, relDir)
               violations = merge(violations, DirectoryRuleInspector::inspect(ruleConfig, listing, listings))
   return new AnalysisResult(listings, violations)
   ```
4. Reporter renders; runner returns `hasViolations() ? 1 : 0`; any `TreeGuardException` → stderr + 2.

Single scan; rule evaluation is pure in-memory over the listing map. `max_total_files`/`max_depth` derive from map keys (prefix `relDir . '/'`), so no second filesystem pass.

```
- For name violations, rename or relocate the offending entries to satisfy the configured patterns.

   actual: 82
   limit: 20

   action: Split the directory into cohesive subdirectories or relocate files until the count fits the limit.
```
`AiViolationFormatter` omits the `actual:`/`limit:` lines when null (name-based rules). `AiViolationAction` maps rule id → imperative action: max_files/max_dirs → restructure/flatten; max_total_files → split the subtree; max_depth → promote deeply nested directories; disallowed_/denied_ file/dir → rename, relocate, or delete; missing_required_file → create the file; empty_directory → delete or populate; file_case/dir_case → rename to the convention; default fallback → restructure to satisfy the pattern.

**text** (`TextReporter`): `TreeGuard passed. No violations found.` / `TreeGuard found N violations.` + `Summary: %d directories, %d files.` + per violation `\n%s [%s]\n  pattern: %s\n  %s\n  Actual: %d, Limit: %d` (actual/limit line omitted when null).

**json** (`JsonReporter`): `{status, summary: {directories, files, violations}, violations: [{path, rule, pattern, actual, limit, message}]}` with `JSON_PRETTY_PRINT | JSON_UNESCAPED_SLASHES`; `actual`/`limit` emitted as `null` for name rules.
