Implement the following plan:

# tree-guard: ディレクトリ/ファイル構造制約ツール + 理想設定によるドッグフーディング

## Context

php-ai-toolkit に、ディレクトリ/ファイル構造の制約を検査する新 CLI ツール **tree-guard** を追加する。目的は、AI エージェントが生成しがちな構造の乱れ(ディレクトリ肥大化、命名逸脱、必須ファイルの欠落、深すぎるネスト、空ディレクトリ等)を CI で機械的に検出すること。

ユーザー決定事項:
- **実装形態**: php-ai-toolkit 内の第2 CLI(LocGuard パターンを踏襲)
- **名前**: tree-guard(`bin/tree-guard` + `tree.yaml` + `src/TreeGuard/` + namespace `PhpAiToolkit\TreeGuard`)
- **v1 制約**: ファイル数上限・ディレクトリ数上限・命名 allow/deny・必須ファイル + 階層深さ上限・空ディレクトリ検出・合計ファイル数上限 + 追加で有用なもの(→ ディレクトリ名の allow/deny、ファイル/ディレクトリ名のケース規約を追加)
- **ドッグフーディング**: 「現状が通る設定」ではなく、**ベストプラクティスから理想の設定を設計し、それを本プロジェクトに適用して検知の妥当性を推論し、真陽性はプロジェクト側をリファクタリングして pass 状態にする**ところまでが本タスクの範囲

PHPStan ルール方式は不採用(PHPStan は解析対象 PHP ファイルしか見えず、ディレクトリ単位の集計・非 PHP ファイル・空ディレクトリを検査できない)。

## テンプレート

`src/LocGuard/` を忠実に移植する。参照必須ファイル:
- `src/LocGuard/Cli/Application.php` — CLI 層全体と DI/テスト用 closure 注入の雛形
- `src/LocGuard/Config/ConfigLoader.php` — YAML ロード/検証スタイル(`Invalid tree.yaml: ...` メッセージ、`TreeGuardException`、exit 2)
- `src/LocGuard/Analysis/Violation.php` — PHP 8.0 の `__get()` + `@property-read` + `/** @readonly */` promoted private プロパティの値オブジェクト定型
- `tests/Unit/LocGuard/Cli/ApplicationTest.php` — 一時ディレクトリツリー構築 + stdout capture closure のテストパターン
- `bin/loc-guard` — バイナリの雛形(PHP_VERSION_ID ガード → 3 段 autoload 探索 → `new Application(getcwd())` → `exit($app->run($argv))`)

Exit code: 0 = pass / 1 = violations / 2 = 設定・実行時エラー。レポーターは `ai`(デフォルト)/`text`/`json`。Shared/AgentDetector は使わない(LocGuard 同様、deptrac で依存なしレイヤーにする)。

## tree.yaml スキーマ

```yaml
paths:                      # list<string>, default ['src']; config ディレクトリ相対
  - src
exclude: []                 # LocGuard 同様の fnmatch glob(相対パス全体に対して)。マッチしたファイルは無視、ディレクトリはサブツリーごと除外
rules:                      # ルールブロックの配列, default []
  - path: 'src/*'           # 必須。ディレクトリマッチパターン(下記セマンティクス)
    max_files: 25           # int>=1: 直下のファイル数上限
    max_dirs: 10            # int>=1: 直下のサブディレクトリ数上限
    max_total_files: 200    # int>=1: 再帰的な合計ファイル数上限
    max_depth: 3            # int>=1: マッチしたディレクトリ基準のネスト深さ上限
    allow: ['*.php']        # 直下ファイル名(basename)の許可 glob。全ファイルがいずれかにマッチ必須
    deny: ['*Helper.php']   # 直下ファイル名の禁止 glob
    allow_dirs: ['[A-Z]*']  # 直下ディレクトリ名の許可 glob
    deny_dirs: ['Helpers']  # 直下ディレクトリ名の禁止 glob
    require: ['README.md']  # 直下に存在必須のファイル名(完全一致)
    forbid_empty: true      # bool, default false: 空ディレクトリ禁止
    file_case: pascal       # pascal|camel|snake|kebab
    dir_case: pascal
report:
  reporter: ai              # ai|text|json
  order_by: [path, rule]    # path|rule|actual|limit
```

### 決定済みセマンティクス(docs に明記する)

- **`rules[].path` はセグメント単位マッチ**: パターンと config-root 相対ディレクトリパスを `/` で分割。`**` セグメントは **0 個以上**のセグメントにマッチ(つまり `src/**` は `src` 自身も含む — gitignore との相違として文書化)。それ以外のセグメントは `fnmatch` で 1 セグメントにマッチ(`*` は `/` を越えない)。両端アンカー。例: `src` は src のみ / `src/*` は直下のみ / `**/Rule` は任意の深さの Rule。
- **`exclude` は LocGuard 互換のプレーン fnmatch**(`rules[].path` との違いを文書化)。
- **複数ルールがマッチしたら全部独立に適用**(override/merge なし)。違反には発火元パターンを含めるので個別に識別可能。
- **制約キー欠如 = 未検査**。`allow: []`(空リスト)は「ファイル一切禁止」— absent(null)と空リストを区別して読む。
- **「このファイル名でなければならない」は `require` + `allow` の合成で表現**(`only:` キーは作らない)。
- **境界値は上限ちょうどで pass**(LocGuard 慣例)。`max_files: 0` は無効(≥1)。「0 個」は `allow: []` で表現。
- **depth**: マッチしたディレクトリ基準。サブディレクトリなし = depth 0。超過した**子孫ディレクトリごとに 1 違反**(actual = そのディレクトリ自身の深さ)。
- **forbid_empty**: 除外適用後の直下エントリ(ファイル+ディレクトリ)が 0 件で発火。
- **case 規約**: ファイルは最初の `.` より前の stem で判定(`AiReporter.php` → `AiReporter`)。dotfile はスキップ。regex: pascal `^[A-Z][A-Za-z0-9]*$` / camel `^[a-z][A-Za-z0-9]*$` / snake `^[a-z0-9]+(_[a-z0-9]+)*$` / kebab `^[a-z0-9]+(-[a-z0-9]+)*$`。
- **バリデーション**: rule ブロック内の**未知キーは拒否**(`Invalid tree.yaml: "rules[0]" contains unsupported key "max_file".`)— typo で検査が無効化される事故を防ぐ(LocGuard の未知 limit 無視とは意図的に異なる)。`paths` エントリが存在しない/ファイルの場合はエラー。

## Violation モデルとルール ID

`Violation` フィールド: `path`(違反ディレクトリ or ファイルの相対パス)/ `rule` / `pattern`(発火元ルールの path パターン)/ `actual`(?int)/ `limit`(?int)/ `message`。**`line` フィールドは無し**(LocGuard との相違)。

| rule id | path | メッセージ例(命令形・自己完結) |
|---|---|---|
| `max_files` | dir | `Directory "src/PhpStan/Rule" contains 82 files but the limit is 25. Move or merge files until at most 25 remain.` |
| `max_dirs` | dir | `Directory "src" contains 9 subdirectories but the limit is 8. Merge or flatten subdirectories.` |
| `max_total_files` | dir | `Directory "src/PhpStan" contains 97 files in total but the limit is 80. Restructure or split the subtree.` |
| `max_depth` | 超過子孫 dir | `Directory "src/A/B/C/D" is nested 4 levels below "src" but the limit is 3. Flatten the directory structure.` |
| `disallowed_file` | file | `File "src/notes.txt" does not match any allowed pattern (*.php). Rename, move, or delete it.` |
| `denied_file` | file | `File "src/Foo/BarHelper.php" matches denied pattern "*Helper.php". Rename or remove it.` |
| `disallowed_dir` / `denied_dir` | dir | 上記のディレクトリ版 |
| `missing_required_file` | `<dir>/<name>` | `Directory "skills/setup-toolkit-tree-guard" is missing required file "SKILL.md". Create it.` |
| `empty_directory` | dir | `Directory "src/Empty" is empty. Delete it or add its intended contents.` |
| `file_case` / `dir_case` | file/dir | `File name "my_reporter.php" in "src/Reporting" does not follow the pascal convention. Rename it.` |

## 解析アルゴリズム

1. `ConfigLoader::load` → `TreeGuardConfig`
2. `DirectoryTreeScanner::scan` → 1 回の走査で `array<相対dirパス, DirectoryListing>`
3. `TreeGuardAnalyzer`: 各 rule × 各 listing で `DirectoryPatternMatcher::matches` → マッチしたら `DirectoryRuleInspector::inspect(rule, listing, listings)`(max_total_files/max_depth は listing マップのキー prefix から算出 — 2 度目の FS アクセス無し)
4. Reporter 出力 → `hasViolations() ? 1 : 0`、`TreeGuardException` は stderr + 2

## 理想設定の設計(ベストプラクティスと根拠)

「現状が通る値」ではなく原則から導いた閾値を設定し、違反はプロジェクト側を直す。

| 制約 | 理想値 | 根拠 |
|---|---|---|
| `max_files` | **25** | ディレクトリ一覧が 1 画面 / 1 回の `ls` で認知できる上限。AI エージェントがディレクトリを列挙したとき、82 件では凝集の手がかりがなく prefix 推測に頼ることになる。本リポジトリの健全なディレクトリは 2〜19 件に収まっており、25 は「健全域 + 余裕」かつ既知の問題箇所(82/33 件)を確実に検知する値 |
| `max_dirs` | **20** | サブディレクトリ一覧は「概念の索引」でありファイルよりスケールするが、20 を超えたら索引自体の再編が必要 |
| `max_depth` | **3**(paths ルート基準) | 現在の最深(`src/PhpUnit/TestReporter/Subscriber` 等)= 3。FQCN の長さと探索コストを抑える実用上限 |
| `max_total_files` | **250**(`src/*` 単位) | 1 ツール(サブシステム)が 250 ファイルを超えたら独立パッケージ化を検討すべき規模 |
| `allow` / `file_case` | src は `*.php` + pascal、tests は `*Test.php` + pascal | PSR-4 / 既存規約の機械的強制 |
| `deny` | `*Helper.php` 等の禁止サフィックス | ForbidClassLikeNameSuffixRule と重複するが、tree-guard 単体導入のプロジェクトでも効く防衛線(本リポジトリでは 0 件) |
| `forbid_empty` | true | 空ディレクトリは意図の残骸 |
| `require` | skills/* に `SKILL.md` | skill はディレクトリ scan で自動発見されるため、SKILL.md 欠落は静かな機能欠損になる |

### 本リポジトリ用 tree.yaml(理想設定)

```yaml

rules:

  reporter: ai
  order_by: [path, rule]
```

## 現状ツリーへの適用結果と検知の妥当性推論(計測済み)

理想設定を現在のツリーに当てると違反は**ちょうど 4 件**(他は全 pass。命名は全て PascalCase、空ディレクトリ無し、深さ最大 3、src/PhpUnit/TestReporter は 19 ≤ 25):

| 検知 | actual/limit | 妥当性判定 | 対応 |
|---|---|---|---|
| `src/PhpStan/Rule` max_files | 82 / 25 | **真陽性**。21 個のルールクラス + 61 個のコラボレータがフラットに混在。公開エントリポイントと内部実装の区別がなく、1 ルールのコラボレータを探すには名前の prefix 推測が必要。ルール追加のたびに悪化する | リファクタリング(下記) |
| `tests/Unit/PhpStan/Rule` max_files | 82 / 25 | 真陽性(上記のミラー) | ミラー移動 |
| `src/LocGuard/Analysis` max_files | 33 / 25 | **真陽性**。トークン走査・複雑度計算・関数/クラスメトリクス収集・違反ビルダー・値オブジェクトが混在 | リファクタリング(下記) |
| `tests/Unit/LocGuard/Analysis` max_files | 33 / 25 | 真陽性(上記のミラー) | ミラー移動 |

**偽陽性リスクの検討(閾値側を直すべきでないことの確認)**:
- `docs/rules`(21 ファイル)と リポジトリルート(27 ファイル、うち 6 つは意図的な `composer.lock.php-8.x`)は v1 の `paths` に含めない。ルートのロックファイル群は「ファイル数が多い = 悪」ではない例であり、閾値を歪めてまで対象に含めない判断根拠として docs/tree-guard.md に記載しない(設定の paths 選定理由として PR 説明に書く)。
- `src/PhpStan/Rule` トップに 21 ルールクラスを**残す**構成(下記)は 25 以下で pass する。将来 25 ルールを超えたら、そのときこそドメイン分割(TestClass 系 / Comment 系…)が必要という正しいシグナルになる。

## テスト計画

- **LocGuard のテストスイートに合わせる**(`tests/Unit/LocGuard/` 検証済): テストメソッド内で `sys_get_temp_dir() . '/treeguard-…' . bin2hex(random_bytes(4))` に実ツリーを構築、stdout/stderr capture closure を注入。**cleanup の try/finally と `#[Medium]` は LocGuard テストでは使われていない**ので付けない。`tests/Fixture/` は使わない。
- 46 クラス全てに `tests/Unit/TreeGuard/<Sub>/<Class>Test.php` を 1:1 で対にする(SrcUnitTestPairRule が自己適用で強制。interface `Reporter` にも `ReporterTest` が要る)。final、`#[CoversClass]` + 網羅的 `#[UsesClass]`、プロパティ/定数/ヘルパー/trait/Reflection/制御構文禁止、メソッド名 `test` + PascalCase、src の各 public メソッド `foo()` に `testFoo*` を最低 1 つ。
