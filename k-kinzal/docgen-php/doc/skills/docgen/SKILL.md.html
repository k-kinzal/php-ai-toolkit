DocGen

Run the installed CLI from the target project's root. Read its composer.json autoload maps and existing documentation command to preserve the intended scope. Use the project's composer docgen script when present; otherwise invoke the CLI:

vendor/bin/docgen --help
vendor/bin/docgen
vendor/bin/docgen --serve

The default run documents . and packages/* into build/docs. Preview serves the generated site at 127.0.0.1:8090 until interrupted.

Command rules

  • DocGen has no configuration file; pass settings as CLI options.
  • --packages selects directories with a composer.json. Production PSR-4 sources get API pages; autoload-dev sources get linkable source pages only.
  • Quote globs. Explicit --packages replaces the defaults; repeated glob options append values. --vendor and --vendor-dev select Composer package names, such as 'acme/*', and are opt-in.
  • Keep the cache (build/docgen-cache by default) outside the published output.
  • --public-api selects declarations tagged @visibility public; it still includes whole source files and Markdown documents, so it does not redact them.

After generation, check the reported package count, index.html, and a relevant symbol or source page. Exit 2 means an invalid command, input, or runtime error; read the DocGen error: message before retrying.
