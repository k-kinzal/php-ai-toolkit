PHPStan Configuration

PHPStan configuration generated by the /setup-toolkit-phpstan skill.

Project Configuration

A project loads one file:

includes:
    - vendor/k-kinzal/php-ai-toolkit/extension.neon

The extension is the baseline, not a menu of settings to copy into each project. It enables PHPStan at level max, the official strict rules, every toolkit rule, checked-exception analysis, and the aiRules error formatter. Keeping those settings in the extension means a toolkit upgrade improves every project without leaving old copied configuration behind.

Analysis paths remain a fact about the target repository. Put its production and test autoload roots on the Composer command:

{
    "scripts": {
        "phpstan": "phpstan analyse src tests --memory-limit=512M"
    }
}

Use the real roots from composer.json when they are not src and tests. Likewise, read composer config vendor-dir and replace the leading vendor in the include when the project uses a custom directory. Once loaded, the extension resolves strict-rules relative to its own installed package rather than assuming the default Composer layout.

Baseline

Maximum analysis level and strict rules

Level max catches the complete set of PHPStan type errors. The official strict rules add bug-prone constructs that PHP accepts, including loose comparisons, implicit array creation, unsafe conditions, and variable variables. Both are enabled by the toolkit extension and must not be repeated or weakened in a target configuration.

Toolkit rules

The extension registers the rules designed around recurring AI-generated defects: weak tests, hidden control flow, generic naming, undocumented exception flow, suppression comments, and source/test drift. See PHPStan Rules for the complete list and identifiers.

AI error formatter

The same extension selects aiRules. Agent runs receive compact, actionable findings; human runs receive source context and colour. A target project does not include error-formatter.neon separately.

Checked exceptions

Checked-exception analysis is off in stock PHPStan and is not part of level max or strict-rules. The extension enables it with:

  • missingCheckedExceptionInThrows, so checked exceptions must be caught or declared;
  • tooWideThrowType, so stale @throws tags fail;
  • implicitThrows: false, so absent @throws means “throws nothing”; and
  • unchecked LogicException, RuntimeException, Error, Random\RandomException, and PHPUnit mock exceptions.

Toolkit exception rules close the common escape hatches: empty or broad catches, generic @throws, unchained rethrows, and tests that expect broken-code families.

Project-Specific Additions

Add a setting only when it describes a real property of the project and cannot be derived from its Composer command. Typical examples are a bootstrap file, a narrow fixture exclusion, supported PHP version bounds, or custom rule markers for a non-standard source/test layout.

Project additions may make the baseline stricter. They must not lower the level, disable strict or toolkit rules, widen broad-catch boundaries, or add ignores merely to make adoption pass. Introducing the toolkit also does not justify changing a released public interface, product documentation, or AGENTS.md.

Extension Installer

The standard setup includes the toolkit explicitly and does not require phpstan/extension-installer. When another PHPStan package requires that plugin, configure it to ignore both k-kinzal/php-ai-toolkit and phpstan/phpstan-strict-rules; the toolkit extension already loads both, and PHPStan rejects duplicate includes.
