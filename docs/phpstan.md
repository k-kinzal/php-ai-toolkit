# PHPStan Configuration

PHPStan configuration generated by the `/setup-toolkit-phpstan` skill.

## Project Configuration

A project composes the standard baseline explicitly:

```neon
includes:
    - vendor/phpstan/phpstan-strict-rules/rules.neon
    - vendor/k-kinzal/php-ai-toolkit/extension.neon
    - vendor/k-kinzal/php-ai-toolkit/rules.neon

parameters:
    level: max
```

Read `composer config vendor-dir` and replace the leading `vendor` when a project
uses a custom Composer directory. Analysis paths remain a fact about the target
repository, so put its production and test autoload roots on the Composer command:

```json
{
    "scripts": {
        "phpstan": "phpstan analyse src tests --memory-limit=512M"
    }
}
```

Use the real roots from `composer.json` when they are not `src` and `tests`.

## Configuration Responsibilities

### `phpstan.neon`

The project configuration composes the three public rule/extension files and
selects level `max`. It is also the correct place for project facts such as
bootstrap files, supported PHP versions, generated fixture exclusions, and
non-standard namespace or path conventions.

### `extension.neon`

The extension file registers the agent detector and the `ai` error formatter.
Agent runs receive compact, actionable findings; human runs receive source
context and colour. This file deliberately does not register toolkit rules or
PHPStan strict-rules.

### `rules.neon`

The rules file owns checked-exception policy, toolkit rule parameters, rule
services, and conditional tags. All rules are enabled by default:

```neon
parameters:
    toolkit:
        allRules: true
        forbidEmptyCatch:
            enabled: %toolkit.allRules%
```

Every rule has its own `toolkit.<rule>.enabled` switch. `allRules: false`
provides an opt-in starting point, while an individual value can override the
shared default:

```neon
parameters:
    toolkit:
        allRules: false
        forbidEmptyCatch:
            enabled: true
```

Toolkit adoption uses the default with all rules enabled. Disabling a rule is a
deliberate project policy decision, not a way to make an initial run green.

### Maximum analysis level and strict rules

Level `max` catches the complete set of PHPStan type errors. The official strict
rules add bug-prone constructs that PHP accepts, including loose comparisons,
implicit array creation, unsafe conditions, and variable variables. They are
explicit includes so each responsibility remains visible in the project config.

### Checked exceptions

Checked-exception analysis is off in stock PHPStan and is not part of level `max`
or strict-rules. `rules.neon` enables it with:

- `missingCheckedExceptionInThrows`, so checked exceptions must be caught or
  declared;
- `tooWideThrowType`, so stale `@throws` tags fail;
- `implicitThrows: false`, so absent `@throws` means “throws nothing”; and
- unchecked `LogicException`, `RuntimeException`, `Error`,
  `Random\RandomException`, and PHPUnit mock exceptions.

Toolkit exception rules close the common escape hatches: empty or broad catches,
generic `@throws`, unchained rethrows, and tests that expect broken-code families.

## Project-Specific Additions

Custom settings are nested under `parameters.toolkit`:

```neon
parameters:
    toolkit:
        testNamespacePrefixes:
            - 'App\Tests'
        restrictedTestNamespacePrefixes:
            - 'App\Tests\Unit'
            - 'App\Tests\Integration'
        srcMarker: '/app/'
        unitTestMarker: '/tests/Unit/'
```

Only add a setting when it describes a real property of the project. Introducing
the toolkit does not justify changing a released public interface, product
documentation, or `AGENTS.md`.

## Extension Installer

The standard setup includes the toolkit and strict-rules explicitly and does not
require `phpstan/extension-installer`. When another PHPStan package requires that
plugin, configure it to ignore both `k-kinzal/php-ai-toolkit` and
`phpstan/phpstan-strict-rules`; otherwise PHPStan receives duplicate includes.
